# 검증 기록

## 입력과 공개 범위

2026-10-15에 `AI_Credit/FICC_Monitor.html`과 `data_info.xlsx`의 완전본을 확인했습니다. Excel 파일 크기는 11,485,524바이트이며 ZIP 구조 검사를 통과했습니다. 원본 파일과 실제 데이터로 만든 중간 결과는 공개 저장소 밖에서만 사용했습니다.

공개 HTML은 날짜·값·원본 행 배열이 비어 있으며 기존 260개 지표의 매핑 정의만 포함합니다. 브라우저 업로드 시 신규42개까지 총302개를 인식합니다. 원본 Excel의 작성자·개인 경로·숨김 시트·비공개 Drive URL은 공개 코드에 없습니다.

## 브라우저·배포 검증 상태

GitHub Actions의 Chromium 통합 테스트 9개가 모두 통과했습니다. 실행: https://github.com/kurt1183/econ/actions/runs/38665220259 (검증 코드 커밋 47bc13e99c986676b8cad60c23db3cc5880e2b46). 302개 합성 계열·96일의 XLSX를 사용했으며 JavaScript 런타임 오류와 업로드 후 외부 통신 요청이 없었습니다. 1440px 화면 캡처를 직접 확인했습니다. 현재 작업 환경의 로컬 브라우저 제어는 제공되지 않아 실행은 GitHub의 Chromium에서 수행했습니다.

| 필수 항목 | 현재 근거와 제한 |
| --- | --- |
| 공개 홈페이지 접속 | 병합 승인·Pages 설정·배포 전이므로 미검증 |
| JavaScript 런타임 오류 | 구문 검사 및 Chromium 통합 9개 경로에서 런타임 오류 없음 |

| 실제 Excel 값 | 1,860,320셀 전수 일치 |
| 날짜 변경 차트/계산 | 기간 모듈 및 Chromium에서 날짜 변경·차트·통계·CSV 반영 통과 |
| 기간·크레딧 계산 | 실제 데이터와 기준 계산 일치, 단위 전제 별도 |

| 새로고침 | Chromium에서 공개 페이지 새로고침 시 빈 상태, 저장 HTML 오프라인 재개방·새로고침 통과. 배포 후 검증 대기 |

GitHub CI에는 실제 Excel을 넣지 않습니다. CI 합성자료로 업로드가 통과해도 실제 11MB Excel의 브라우저 메모리·처리시간·전체 시각 검증을 대신하지 않습니다. 독립 파서 두 경로가 같은 파일을 읽은 일치는 원천 금융자료가 정확하다는 독립 검증도 아닙니다.

## 재현

```bash
python3 scripts/build.py
node tests/public-artifact.cjs
npm test
```

NumPy/SciPy/openpyxl이 있는 개인 환경에서는 다음과 같이 실제 원본을 비공개 경로에서 대조할 수 있습니다. 출력 경로를 저장소 안으로 지정하면 거부합니다.

```bash
python3 scripts/reference_check.py --workbook /private/data_info.xlsx --output /private/ficc-validation
```

실제 원본 및 계산 결과를 PR·Actions artifact·공개 로그에 첨부하지 마십시오.

## 검토에서 수정한 오류

- 업로드 범주명이 HTML로 해석되던 경로를 이스케이프하고 안전한 범주 사전을 사용했습니다.
- 빈 상태에서 실패한 업로드 후 HTML 저장 버튼이 켜지던 오류를 수정했습니다.
- 저장 HTML 재개방 시 신규 EQUITY 범주가 선택 목록에서 누락되던 오류를 수정했습니다.
- 수치 오차 범위의 상수 계열이 산점도에서 큰 분산으로 확대되지 않도록 표준편차 판정과 축 여백을 일치시켰습니다.
- 저장 HTML의 추가 지표가 다음 업로드의 필수 지표로 굳어지지 않도록 기준 260개 정의만 필수로 유지했습니다.

빈 상태 오류·신규 범주·저장 재개방은 Chromium 회귀검증에 포함됐습니다. 최종 변경 이후 수치 모듈은 실제 데이터 대조 당시 해시와 동일합니다.
